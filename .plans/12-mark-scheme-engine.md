# Mark Scheme Engine Plan

## Feature Intent

The Mark Scheme Engine automatically compiles publication-quality marking guides alongside every exam paper. Each question's worked solution — authored alongside the item or generated by AI — is extracted into a structured, three-column table: Question & Part Identifier, Detailed Working / Indicative Content, and Mark Allocation with taxonomic classification.

Departments configure their own mark classification codes (M, A, B, DM, FT, C) and column layouts via JSONB, so a Cambridge Maths department can produce CIE-standard tabular schemes while a humanities department uses level-based rubric bands. The mark scheme is locked to the exact `ItemVersion` used in the exam, so it remains correct even if the source item is later revised.

Variant exams automatically receive their own correlated mark schemes, with variant-specific parameter values substituted into the worked solutions.

## Data Model

```ruby
class MarkScheme < ApplicationRecord
  belongs_to :exam
  belongs_to :exam_variant, optional: true
  # columns: compiled_pdf_path
  has_many :mark_scheme_rows, dependent: :destroy
end

class MarkSchemeRow < ApplicationRecord
  belongs_to :mark_scheme
  belongs_to :item_version
  # columns: question_label, working_content (text), marks_total, mark_classifications_json
end
```

## Mark Scheme Structure (JSONB-Driven)

The `Department#mark_scheme_config` JSONB column defines the mark scheme format:

```json
{
  "classifications": [
    { "code": "M", "label": "Method", "description": "Correct approach" },
    { "code": "A", "label": "Accuracy", "description": "Correct result" },
    { "code": "B", "label": "Independent", "description": "Standalone correct statement" },
    { "code": "DM", "label": "Dependent Method", "description": "Method relying on prior M mark" },
    { "code": "FT", "label": "Follow Through", "description": "Error carried forward accepted" },
    { "code": "C", "label": "Compensatory", "description": "Correct final answer despite missing working" }
  ],
  "column_order": ["question", "working", "marks"],
  "rubric_levels": [
    { "name": "Level 1", "range": [1, 3] },
    { "name": "Level 2", "range": [4, 6] }
  ],
  "page_format": {
    "paper": "A4",
    "font": "Times-Roman",
    "font_size": 10,
    "margins": { "top": 20, "bottom": 20, "left": 20, "right": 20 }
  }
}
```

There is no `MarkClassification` enum. Classification codes, column layouts, and rubric bands are all defined per-department in JSONB. The PDF renderer reads this config and adapts its output accordingly.

`MarkSchemeRow#mark_classifications_json` stores the per-row classification breakdown as JSONB:

```json
[
  { "classification": "M", "mark_value": 1, "description": "Correct substitution" },
  { "classification": "A", "mark_value": 1, "description": "Correct result" },
  { "classification": "FT", "mark_value": 1, "description": "Error carried forward" }
]
```

## Compilation Process

### Auto-Extraction
```ruby
class MarkSchemeCompiler
  def compile(exam_id)
    exam = Exam.includes(exam_items: :item_version).find(exam_id)
    mark_scheme = exam.build_mark_scheme

    exam.exam_items.each do |exam_item|
      iv = exam_item.item_version
      mark_scheme.mark_scheme_rows.create!(
        question_label: exam_item.position_label,
        working_content: iv.worked_solution_html,
        marks_total: exam_item.marks || iv.item.marks,
        mark_classifications_json: parse_mark_allocations(iv.worked_solution_markdown)
      )
    end

    generate_pdf(mark_scheme)
  end
end
```

### PDF Output
Rendered by `PdfKit::MarkSchemeRenderer`, which reads the department's `mark_scheme_config`:

- **Column structure:** determined by `column_order` array
- **Classification legend:** rendered from `classifications` array at top of each page
- **Rubric layout:** indented sub-tables per `rubric_levels` band
- **Formatting defaults:** `page_format` provides paper size, font, margins — overridable per department

## Integration
- Triggered automatically after exam assembly completes
- Manual regeneration if items change (locked exams prevent auto-update)
- Variant mark schemes linked to variant exams via `exam_variant_id`

## Storage Impact
- Mark scheme rows: ~500 bytes per item × 50 items = 25KB per exam
- Mark classifications JSONB: ~200 bytes per row
- PDF output: ~300KB per mark scheme × 100 exams = 30MB
